CHAPTER 16

转型与面试指南

做出什么 > 学过什么

招聘范式正在从“我学过什么”转向“我做出了什么、怎么验证、怎么写进简历、怎么讲给面试官听”。对转型程序员来说，最有效的准备是：亲手落地一个可讲清楚取舍与指标的小型 Agent 项目。

1
建立心智模型
吃透：Agent=Model+Harness、Workflow vs Agent、Agent Loop、上下文工程、工具/ACI、评测。能用自己的话讲清“为什么不要为了 Agent 而 Agent”。
2
打通技术栈
至少一条主线：直接用 LLM API 实现 ReAct/工具循环；熟悉 LangGraph 或 Claude/Codex Agent SDK；掌握 RAG（分块→混合检索→重排→引用）；了解 MCP。
3
做出可验证的项目
选一个有“清晰成功标准 + 反馈闭环 + 人审”的真实场景端到端落地，量化效果（成功率/时延/成本），写清失败模式与迭代过程。
4
讲出工程深度
面试不是背概念，而是展示取舍：为什么加/不加子代理、如何做压缩、如何设计防呆工具、如何评测。准备好“踩过的坑与修复”。
高频
概念辨析
Workflow vs Agent；ReAct/ToT 演进；上下文工程 vs 提示工程；RAG vs agentic 检索。
工程
可靠性设计
死循环三层防御、状态持久化、SSE 流式输出、工具幂等、成本与延迟控制。
评测
如何度量
结果评测 vs 过程评测、LLM-as-Judge、回归集、可观测与 tracing、灰度部署。
面试常见追问与准备方向
  • 你的 Agent 项目差在哪？——面试官六维：问题定义、方案设计、工程实现、评测验证、可靠性、复盘迭代
  • 为什么用多智能体 / 为什么不用？——围绕“是否花够 token、协调成本、可观测性”作答
  • 怎么处理幻觉与不可靠检索？——接地、引用、重排、人审、评测闭环
  • 上下文爆了怎么办？——压缩 + 结构化笔记 + 子代理，并说明各自适用场景
  • 如何证明改动有效？——小样本评测起步、指标对比、失败案例回灌
一句话准备心法
把每个知识点都落到“我做了什么、我怎么验证、我踩了什么坑、我怎么改进”的四段式叙事上——这正是面试官想听的实战型工程师的故事线。
