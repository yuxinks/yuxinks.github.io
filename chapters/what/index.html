CHAPTER 02

什么是真正的 Agent

Workflows 与 Agents 的关键区别

业界对 “Agent” 定义不一。Anthropic 给了一个非常好用的架构区分：把二者都归为 agentic systems，但设计哲学完全不同。理解这条边界，是避免过度设计的第一步。

Workflows（工作流）
  • LLM 与工具通过“预先写死的代码路径”编排
  • 可预测、可控、易调试
  • 适合定义清晰、边界明确的固定任务
Agents（自主代理）
  • LLM 动态决定自己的流程与工具使用
  • 灵活、可处理无法预知步数的开放任务
  • 成本更高、错误可能累积，需要护栏
一个好用的极简定义
Agent = LLM 在循环中自主使用工具（LLMs autonomously using tools in a loop）。更工程化的写法：Agent = Model + Harness。模型是你从厂商“租用”的部分，Harness 才是你真正“拥有”并可持续改进的部分。
基座
Augmented LLM（增强的 LLM）
一切 agentic 系统的基础积木：在 LLM 之上叠加检索(Retrieval)、工具(Tools)、记忆(Memory)，让模型主动发起搜索、选择工具、决定保留什么信息。
内核
Agent Loop（循环）
思考 → 选工具 → 执行 → 读取环境反馈 → 再决策。循环的停止条件、错误恢复、步数预算，决定了 Agent 是否可靠。
接口
ACI（Agent-Computer Interface）
类比 HCI。工具的定义、文档、参数格式，就是给模型用的“界面”，值得投入和写提示词同等的工程精力。
落地时的三条核心原则（Anthropic）
  • 保持简单：Agent 的设计要尽量简洁，能简单就不要复杂
  • 重视透明：显式展示 Agent 的规划步骤，让行为可被观察和调试
  • 打磨接口：通过完善的工具文档与测试，认真设计 Agent-Computer Interface
