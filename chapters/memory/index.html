CHAPTER 05

记忆与长时程任务

跨越上下文窗口，保持连贯与目标导向

长时程任务（大型代码迁移、系统性研究，持续几十分钟到数小时）需要的 token 会超出上下文窗口。等“更大窗口”不是办法——只要有性能要求，任何大小的窗口都会被上下文污染与信息相关性问题困扰。三类技术直接应对：压缩、结构化笔记、多智能体。

第一杠杆
Compaction 压缩
接近窗口上限时，把对话总结、用摘要重启新窗口。保留架构决策、未解决的 bug、实现细节，丢弃冗余工具输出。先最大化召回、再提升精度地调提示。最安全轻量的一招：清理深层历史里的原始工具结果。
持久化
结构化笔记 / Agent 记忆
Agent 定期把要点写到窗口之外的笔记（如 NOTES.md、to-do），后续再拉回上下文。Claude 玩 Pokémon 能跨上千步维持目标计数与地图，靠的就是自管理记忆。
隔离
子代理架构
主 Agent 持高层计划，子 Agent 在干净窗口里做深入探索（可能用几万 token），只回传蒸馏后的摘要（常 1–2k token）。搜索细节被隔离，主 Agent 专注综合。
怎么选
  • 需要大量来回交互 → 压缩(Compaction)
  • 有清晰里程碑的迭代开发 → 结构化笔记
  • 可并行探索的复杂研究/分析 → 多智能体架构
工程实现要点
记忆工具往往以“文件系统 + 会话外持久化”落地；跨会话保存项目状态、逐步积累知识库。注意：压缩过度会丢掉“当时不起眼、后来才关键”的细微上下文，取舍是这门手艺的核心。
