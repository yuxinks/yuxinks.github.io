CHAPTER 14

Agent 的持续进化

把执行经验转化为持续的改进

大多数 Agent“每次从零开始”，同样类型的错误会反复出现。持续进化的目标是把运行中积累的经验，系统性地沉淀回系统——从“会用”走向“越用越强”。核心不是等模型升级，而是经营好你这一侧的学习闭环。

1
执行与记录
全量保存轨迹：提示、工具调用、结果、失败点、人工纠正。没有可观测的记录，就谈不上学习。
2
评测与失败分析
用小样本评测快速定位“反复出现的失败模式”，每个重复错误都当作一个可修复的系统缺陷。
3
沉淀经验
把结论写成可复用资产：结构化笔记 / 记忆、技能库(skills)、案例库、评测用例、linter 规则或结构测试。
4
回灌 Harness / 提示 / 工具
让沉淀生效于下一次运行——用模型改写工具描述、把约定加进 AGENTS.md、把偏好变成自动检查。
5
再执行并度量
用一致指标(成功率/时延/成本)对比改动前后，确认进化有效，形成自我校正的闭环。
记忆
经验与记忆沉淀
窗口之外的笔记/知识库让 Agent 跨会话保留项目状态与教训，是进化的“长期存储”。
技能
技能库与案例库
把成功做法固化为可检索、可复用的技能/示例，遇到相似任务直接调用而非重推。
自我改进
自动化 Harness 进化
让模型诊断失败、重写工具描述、生成新检查。呼应“重复错误 = Harness bug”，把修复左移到系统层。
进化的风险：自我强化偏差与回滚
若把“错误经验”也沉淀回系统，会形成自我强化的坏模式。必须有评测护栏、灰度验证与可回滚机制：任何“自动改进”都要先证明指标变好，才能永久生效；否则保留旧版本。

把这条闭环与 Harness 工程、评测、记忆/上下文三章连起来看：进化不是单一功能，而是“可观测 → 可评测 → 可沉淀 → 可回灌”的系统能力。做到这四步，你的 Agent 会随时间稳定变强，而不只是依赖下一代模型。
