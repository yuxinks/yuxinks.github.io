CHAPTER 01

为什么需要 Agent

传统自动化的边界，与 LLM 带来的新能力

普通脚本和固定工作流擅长“可预知路径”的任务。但真实世界里大量任务是无法提前写死步骤的：需要理解模糊意图、访问外部信息、根据中间结果动态调整。Agent 的价值，正是让模型在“环境反馈的循环”里自主使用工具去解决这类开放问题。

痛点
固定流程难以为继
改哪些文件、需要几步、要走哪条分支，事先根本无法写死。硬编码 if-else 越来越脆。
能力
理解 + 行动
LLM 不只生成文本，还能读语义、调工具、看结果、再决策，把“对话”和“执行”结合起来。
价值
规模化可信任务
在有明确成功标准、可反馈、有人类监督的场景里，Agent 能把重复的复杂工作规模化。
先说结论：不要为了 Agent 而 Agent
Agent 往往用延迟和成本换取更强的任务表现。很多场景优化好单次 LLM 调用（配上检索与少量示例）就够了。只有当“简单方案明显不够用”时，才逐步叠加更复杂的 agentic 能力。
Agent 最能创造价值的四类特征
  • 既需要“对话”又需要“行动”，而不是一次性问答
  • 有清晰、可衡量的成功标准（能验证对错）
  • 存在反馈闭环，能让 Agent 基于结果迭代
  • 可以嵌入合理的人类监督，风险可控

两个已被验证的高价值方向：一是客户支持（对话式交互 + 工具拉取订单/知识 + 可程序化执行退款/建工单，且解决率可度量）；二是编码 Agent（代码能被自动化测试验证，Agent 可以基于测试结果迭代，问题空间结构化，质量可客观度量）。
